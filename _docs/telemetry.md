# OpenTelemetry Architecture & Telemetry Specification

**Project**: Personal Lifecycle Tracker  
**Lifecycle Stage**: Gate 14 — OpenTelemetry Full-Stack Instrumentation & Decoupled Observability

---

## 1. Golden Triangle Resource Attributes

Every telemetry signal (traces, metrics, logs) generated by any service in the Personal Lifecycle Tracker stack MUST include the standard semantic conventions:

| Resource Attribute | Semantic Key | Description | Example Values |
|---|---|---|---|
| **Service Name** | `service.name` | Logical identifier of the component | `api-backend`, `web-frontend`, `caddy-proxy` |
| **Environment** | `deployment.environment` | Deployment lifecycle stage | `development`, `staging`, `production` |
| **Deployed Version** | `service.version` | Release version or commit SHA | `dev-latest`, `20261010-123320-16fea64`, `v1.0.0` |

### Environment Variables
```ini
OTEL_SERVICE_NAME=api-backend
OTEL_RESOURCE_ATTRIBUTES=service.name=api-backend,deployment.environment=development,service.version=dev-latest
OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:4328
OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
```

## 2. Distributed Tracing Topology (W3C Trace Context)

Distributed traces propagate correlation headers across all boundaries using the W3C Trace Context specification (`traceparent` and `tracestate`):

```
[Browser / React Web Client]
       │
       │ (W3C traceparent injected by FetchInstrumentation)
       ▼
[Production Caddy 2 Reverse Proxy]
       │
       │ (traceparent header passed through, X-Request-ID attached)
       ▼
[FastAPI Backend Application]
       │
       │ (FastAPIInstrumentor starts server span, extracts traceparent)
       ▼
[PostgreSQL Database (SQLAlchemy / psycopg2)]
         (Child DB span: query, table, operation latency)
```

## 3. Decoupled Observability Architecture (`observability/`)

The observability infrastructure is isolated in `observability/docker-compose.yaml` with its own lifecycle, network (`personal-lifecycle-observability-net`), and persistence:

- **OpenTelemetry Collector Contrib (`otel/opentelemetry-collector-contrib:0.95.0`)**:
  - Ingests traces, metrics, and logs via OTLP gRPC (`:4317` internal / `:4327` host) and OTLP HTTP (`:4318` internal / `:4328` host).
  - Routes traces to Tempo (`tempo:4317`).
  - Converts and exposes metrics to Prometheus (`:8889` internal / `:8899` host).
  - Routes logs to Loki (`http://loki:3100/loki/api/v1/push`).
- **Prometheus (`prom/prometheus:v2.51.0`)**:
  - Scrapes metrics on port `:9090` (host `:9091`).
- **Loki (`grafana/loki:2.9.4`)**:
  - Aggregates logs on port `:3100` (host `:3101`).
- **Tempo (`grafana/tempo:2.4.1`)**:
  - Stores distributed trace spans on port `:3200` (host `:3201`).
- **Grafana (`grafana/grafana:10.4.0`)**:
  - Serves unified visualizations on port `:3000` (host `:3004`).
  - Pre-provisioned datasources: Prometheus, Loki (with traceId derived field), Tempo (with tracesToLogsV2 and tracesToMetrics).
  - Pre-provisioned dashboard: `lifecycle-tracker-overview.json`.

## 4. Excluded / Filtered Routes

Health checks and internal scraping endpoints are excluded from distributed traces to prevent log spam:
- `/health`
- `/healthz`
- `/metrics`
- `/favicon.ico`
